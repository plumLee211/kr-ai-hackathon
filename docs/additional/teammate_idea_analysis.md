# 팀원 아이디어 분석: OOO's Adventure

> 원본: `docs/teammate_idea/custom-game-v2.pdf` (27p)

## 1. 아이디어 요약

**한 줄:** Gemini Game Master와 대화하며 어둠 속 세계에 색을 입히고, 나만의 파티로 보스를 처치하는 개인화 던전 RPG

**태그라인:** "어둠 속에서 시작해, 대화로 세계를 물들이고, 빈칸은 당신이 채운다"

**트랙:** 엔터테인먼트 분야의 Gemini (게임)

---

## 2. 핵심 컨셉

### "대화할수록 세계가 물든다"

| 단계 | 대화 내용 | 화면 변화 | 게임 요소 |
|------|----------|----------|----------|
| Step 1 | "이름을 알려줘!" | 어둠 속 미세한 빛 (10%) | 주인공 이름 + 타이틀 |
| Step 2 | "MBTI가 뭐야?" | 보라빛 스며듦 (30%) | 동료 성격 & 클래스 |
| Step 3 | "좋아하는 동물?" | 보라 그라데이션 + 달 (60%) | 동물 모티브 동료 |
| Step 4 | "멸망하면 뭘 챙길래?" | 마젠타 풀컬러 (90%) | 시작 무기/아이템 |
| 타이틀 전환 | -- | Gemini 4색 폭발 + BGM (100%) | 게임 시작 |

### 색상 진행 시스템

- **배경:** 완전 어둠 -> 보라 틴트 -> 보라 그라데이션 -> 마젠타 -> Gemini 4색
- **텍스트:** 어두움 -> 밝아짐 -> 더 밝아짐 -> 거의 흰색
- **GM 이름:** 회색 -> 파랑 -> 보라 -> 핑크
- **컬러 픽셀:** 거의 없음 -> 조금씩 -> 늘어남 -> 가득 -> 폭발
- **BGM:** 없음 -> 없음 -> 없음 -> 없음 -> 화려한 BGM 시작

## 3. 게임 플로우

### 전반부
```
[타이틀] OOO's adventure          <- 무채색, 무음
    |
[Game Master 대화 4단계]          <- 대화마다 색상 점진적 유입
    |
[*] 설문 완료 -> Gemini 컬러 폭발 + BGM 시작 [*]
    |
[타이틀 전환] 김철수's adventure    <- Gemini 4색 그라데이션
    |
[Gemini 3.1: 파티 + 보스 생성]
[Nano Banana 2 Flash: 캐릭터 에셋]  <- 백그라운드 생성
```

### 후반부
```
[파티 소개 화면]                   <- 보스 아트 백그라운드 생성 중
    |
[바로 보스 스테이지]               <- 잡몹 없음, 즉시 보스전
    |
[턴제 전투] (JRPG 스타일)
    |
[보스 처치]
    |
[Game Master 재등장 + Phase 2 대화] <- 좌우명, 사는 곳 등
    |
[추가 컨텐츠 / 다음 스테이지]
```

### "바로 보스전" 전략
- 시간 제한 (7~8h) -> 잡몹 스테이지 생략, 즉시 보스전
- 데모에서도 임팩트 있음 (심사위원이 3분 내에 전투까지 경험)

## 4. 캐릭터 에셋 시스템

### 2종 구성

| 종류 | 스타일 | 용도 |
|------|--------|------|
| 이동용 도트 | 48x48+ 모던 픽셀 (스타듀밸리/언더테일) | 맵 이동, 파티 소개 |
| 컷신/전투 일러 | 애니메이션 일러스트 (페르소나/파판 택틱스) | 전투 UI, 컷신 연출 |

### 생성 파이프라인
```
[도트 스프라이트]
설문 데이터 -> Gemini 3.1 (캐릭터 설정)
  -> Nano Banana 2 Flash (48x48 모던 픽셀, 정면, 투명배경)
  -> 정지 도트 이미지 출력

[애니메이션 일러스트]
설문 데이터 -> Gemini 3.1 (캐릭터 설정 + 표정 지시)
  -> Nano Banana 2 Flash (애니메이션 일러스트 스타일)
  -> 기본 -> 공격 -> 피격 (순차 생성, 2~3장)
```

### 1 스테이지당 에셋 수량
- 도트 4장 + 일러 10~15장 = **총 14~19장**
- 핵심: 어떤 입력이 들어와도 **같은 세계관의 캐릭터**로 보이게 하는 것

---

## 5. 전투 시스템 -- JRPG 클래식 턴제

- 검증된 방식 (페르소나/파판 택틱스 스타일)
- **핵심은 전투가 아닌 개인화 캐릭터 + 아트** -> 전투는 심플하게
- 전투 UI에 애니메이션 일러스트 배치, 행동/피격 시 표정 변화 연출

### 전투 턴 진행
```
[내 턴] 공격 / 스킬 / 아이템 / 방어
  v
[연출 + 데미지 계산] <- 일러스트 표정 전환
  v
[보스 턴] Gemini 3.1이 상황 기반 행동 결정
  v
[로깅] "턴 3: 김철수 - 얼음창, 바퀴벌레 마왕 - 촉각 휩쓸기"
  v
... 반복 -> [보스 HP 0] -> 클리어!
```

### 보스 AI (Gemini 3.1)
- 매 턴마다 상황을 분석하여 보스 행동 결정
- 플레이어 HP, 사용 패턴, 남은 스킬 등을 고려
- 같은 보스라도 **매번 다른 전투 패턴** -> 리플레이성 확보

## 8. 데모 시나리오 (심사위원 체험 3분)

1. 타이틀 화면: OOO's adventure -- 완전 어둠, 무음 <- "뭐지?"
2. Game Master 등장, 대화 시작 -- 화면에 색이 스며들기 시작 <- 첫 번째 "와"
3. 대화할수록 보라빛 -> 마젠타 세계가 물들어감 <- "대화로 색이 바뀌네?"
4. 설문 완료 -> **Gemini 컬러 폭발 + BGM** + 타이틀 전환 <- 두 번째 "와"
5. 눈앞에서 **모던 픽셀 파티 + 일러스트** 생성 <- 세 번째 "와"
6. **고퀄리티 보스 일러스트** 등장 -> 보스전 1~2턴 체험
7. 보스 처치 -> Game Master 재등장 -> 추가 대화 유도

---

## 9. 차별화 포인트 (팀원 주장)

1. **대화가 세계를 물들인다** -- 설문마다 색상이 스며드는 연출
2. **Gemini가 게임의 얼굴** -- Game Master로 전면 등장
3. **설문 완료 = Gemini 컬러 폭발 + BGM** -- 감각적 보상
4. **일관된 세계관** -- 도트 + 일러 2종, 어떤 입력이든 같은 스타일
5. **대기 시간 0** -- 백그라운드 생성 전략

## 11. 기술적 우려 사항

### A. 이미지 생성 병목
- 1 스테이지에 14~19장 생성 필요
- Nano Banana 2 Flash 1장당 생성 시간이 관건
- 백그라운드 전략이 핵심이지만, **한 장이라도 늦으면 UX 깨짐**

### B. 스타일 일관성 보장
- "프롬프트를 사전 정제"한다고 했지만, 생성형 AI의 특성상 매번 다른 결과
- 특히 도트 48x48은 해상도가 낮아 세밀한 제어가 어려움
- 일러스트도 같은 캐릭터의 기본/공격/피격 표정이 일관되는지 검증 필요

### C. 구현 범위 (7~8시간)
- 설문 UI + 색상 트랜지션 애니메이션
- Gemini API 연동 (Game Master 대화, 캐릭터 설정, 보스 AI)
- Nano Banana 2 Flash API 연동 (이미지 생성 파이프라인)
- 전투 시스템 (턴제 로직, HP/데미지, UI)
- BGM 통합 (Lyria 3)
- 백그라운드 에셋 생성 오케스트레이션
- **매우 빡빡함** -- 우선순위 명확히 잡아야 함

### D. Gemini 3.1 응답 안정성
- Game Master 대화가 자연스럽지 않으면 초반 인상이 무너짐
- 보스 AI가 비합리적 행동을 하면 전투 경험 저하
- 프롬프트 엔지니어링 품질이 게임 품질에 직결

## 12. 종합 평가

### 잘 된 점
- **"대화가 세계를 물들인다"** 컨셉이 감성적이고 데모에서 임팩트 있음
- **Gemini를 Game Master로** 전면 배치 -> 구글 기술 활용이 자연스러움
- **비용 분석**까지 포함한 치밀한 기획
- **백그라운드 생성 전략**으로 대기 시간 최소화 시도
- **데모 시나리오**가 3분 내 "와" 포인트 3개로 설계됨
- **"바로 보스전" 전략**으로 해커톤 시간 제약을 고려한 현실적 스코프 조절

### 보완이 필요한 점
- **구현 범위가 너무 넓음** -- MVP 스코프를 더 줄여야 할 수 있음
- **이미지 생성 품질/속도**에 대한 실험적 검증 없음 (프로토타입 필요)
- **전투 시스템**이 부가적이라면 더 단순화하거나, 아예 전투 없이 "생성된 세계 탐험"으로 갈 수도 있음
- **Phase 2 (보스 후 추가 설문)**는 해커톤 데모 3분에서 보여주기 어려움 -- 있으면 좋지만 구현 우선순위 낮춤
- **Google ADK 미활용** -- 에이전트 오케스트레이션을 ADK로 구현하면 기술 활용도 올라감

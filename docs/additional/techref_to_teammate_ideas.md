## SNS + 설문 하이브리드 개인화 전략

### 핵심 컨셉: SNS = 베이스라인, 설문 = 미세 조정 + 연출

기존 설계의 설문 4개만으로는 개인화 데이터가 부족하다. Instagram + X(Twitter)를 연결하면 Gemini Vision이 시각 취향 + 성격/관심사를 풍부하게 분석할 수 있고, 설문은 이를 보정하면서 "세계가 물드는" 연출을 유지하는 역할을 한다.

### 왜 SNS + 설문 병행인가

| | SNS만 | 설문만 | **SNS + 설문** |
|---|------|-------|---------------|
| 데이터 풍부도 | 높음 | 낮음 | 최고 |
| 게임 몰입감 | "알아서 분석" → 수동적 | 대화로 참여 → 능동적 | **둘 다** |
| "색이 물드는" 연출 | 보여줄 타이밍 없음 | 설문마다 색 유입 | SNS로 베이스 깔고 + 설문마다 추가 |
| 데모 임팩트 | 분석 결과만 보여줌 | 원래 설계 | **"AI가 이미 알고 있었다" + 대화로 확인** |

### SNS 데이터 → 게임 매핑

| 소스 | 추출 | 게임 반영 |
|------|------|----------|
| **Instagram 사진** | Gemini Vision으로 색조/분위기/미적 취향 분석 | 세계관 팔레트, 던전 비주얼 스타일 |
| **Instagram 캡션/해시태그** | 관심사, 라이프스타일 키워드 | 동료 캐릭터 모티브, 아이템 |
| **X 트윗** | 말투, 의견, 유머 스타일 | GM 대화 톤, 보스 도발 대사 |
| **X 좋아요/관심사** | 취향 카테고리 | 보스 모티브, 스토리 테마 |

### Gemini Vision 활용

Instagram 사진을 Gemini Vision에 넣으면 설문 4개보다 훨씬 풍부한 개인화 신호를 추출할 수 있다:

```
"이 사용자의 최근 사진 20장 분석 결과:
 - 색조: 따뜻한 톤 위주 (오렌지, 골드)
 - 주제: 카페, 고양이, 석양
 - 분위기: 차분하고 아늑함
 → 세계관: 황혼빛 고양이 왕국, 보스: 잠들지 않는 카페 주인"
```

### 변경된 데모 플로우

```
[1] Instagram/X 로그인
    → Gemini Vision이 백그라운드에서 사진/트윗 분석
    → 세계관 베이스 팔레트 사전 결정 (어둠 속 10% 빛 시작)

[2] GM 대화 4단계 (기존 설문 유지)
    → "이름을 알려줘!" → 빛 30%
    → "MBTI가 뭐야?" → 빛 60%
    → 단, GM이 SNS 데이터를 이미 알고 있는 듯 대화
      예: "네 사진을 보니 따뜻한 곳을 좋아하는구나... 그럼 이건 어때?"
    → 설문 답변이 SNS 분석을 보정/확정하는 역할

[3] 설문 완료 → Gemini 컬러 폭발
    → SNS 분석 + 설문 답변 종합해서 최종 세계관 확정
```

### 구현 현실성 (본인 계정으로 데모)

| 항목 | Instagram | X |
|------|-----------|---|
| API | Graph API (Meta 개발자 앱 등록) | API v2 (무료 티어) |
| 본인 계정 접근 | 개발자 모드로 즉시 | 개발자 포탈에서 키 발급 |
| 필요 데이터 | 최근 사진 20장 + 캡션 | 최근 트윗 50개 + 좋아요 |
| 사전 캐싱 | 데모 전에 JSON으로 저장 가능 | 동일 |
| 예상 구현 시간 | 1-2h (OAuth + 사진 fetch) | 1h (토큰 발급 + fetch) |

본인 계정이므로 OAuth 심사/승인 문제 없음. 데모 전에 JSON으로 캐싱해두면 안정성 확보.

### SNS 연결로 달라지는 기술 적용

| 기술 | 설문 4개만 | SNS + 설문 |
|------|-----------|-----------|
| **Deep Think** | 적은 입력 깊게 해석 | 대량 데이터 종합 분석 → 더 적합해짐 |
| **Feeling Social** | 성향 추측 수준 | 실제 SNS 어투로 성향 확정 → 정확도 상승 |
| **Lyria 3** | 범용 BGM | Instagram 미적 취향 반영 → 진짜 "내 음악" |

## 음성 개인화: Lyria 3 + TTS API

### 핵심 아이디어: GM의 목소리까지 개인화

Lyria 3가 BGM을 담당한다면, **Game Master의 음성**은 TTS API로 커버한다. 텍스트 채팅 대신 **GM이 직접 말하는** 경험은 데모 임팩트를 한 단계 끌어올린다.

### TTS API 후보 비교

| API | 강점 | 한국어 | 비용 | 해커톤 적합성 |
|-----|------|--------|------|-------------|
| **Google Cloud TTS** | Google 스택 통합, 다양한 음성 | 우수 | $4/100만 글자 (거의 무료) | 높음 (All Google 컨셉) |
| **ElevenLabs** | 최고 품질, 감정 표현, 음성 복제 | 지원 | 무료 티어 10분/월 | 높음 (품질 최고) |
| **Supertone** | 한국어 특화, 자연스러운 감정 | 최우수 | 별도 문의 | 중간 (한국어 최적) |

### 적용 시나리오

**A. Game Master 보이스 (가장 핵심)**

```
[텍스트 GM]  "용감한 모험가여, 이 어둠 속에서 당신의 이름을 알려주시오."
    ↓ TTS API
[음성 GM]  실제 목소리로 대사 재생 + 텍스트 자막 동시 표시
```

- ElevenLabs의 감정 파라미터로 GM 대사에 긴장감/따뜻함/위엄 등을 상황별 조절
- 설문 단계: 부드럽고 신비로운 톤
- 전투 단계: 긴박하고 웅장한 톤
- 승리 후: 따뜻하고 축하하는 톤

**B. 보스 캐릭터 고유 목소리**

보스마다 다른 음성 프로필 적용:
- 드래곤 보스 → 낮고 울림 있는 목소리
- 요정 보스 → 높고 장난스러운 목소리
- ElevenLabs Voice Design으로 캐릭터별 목소리 생성 가능

**C. Lyria 3 + TTS 시너지**

```
[전투 시작]
  Lyria 3: 긴장감 있는 BGM 스트리밍 시작
  TTS: 보스 등장 대사 "감히 내 영역에 발을 들이다니..."
  → BGM 볼륨 자동 조절 (대사 시 낮아짐, 끝나면 올라감)

[승리]
  Lyria 3: BGM이 점층적 고조 → 팡파르
  TTS: GM "축하합니다, [플레이어 이름]! 당신의 첫 번째 승리입니다."
```

### 구현 난이도

| 항목 | 시간 | 비고 |
|------|------|------|
| Google Cloud TTS 연동 | 30분 | API 키만 있으면 즉시 |
| ElevenLabs 연동 | 1시간 | 무료 티어로 데모 충분 |
| 음성+BGM 볼륨 믹싱 | 1시간 | Web Audio API로 구현 |
| 캐릭터별 음성 프로필 | 30분 | 사전에 Voice Design 세팅 |

### 권장 조합

- **All Google 스택 중시:** Google Cloud TTS + Lyria 3 → 심사 기준(Google AI 활용) 최적
- **데모 품질 중시:** ElevenLabs + Lyria 3 → 음성 품질 최고, 감정 표현 우수
- **한국어 데모:** Supertone + Lyria 3 → 한국어 자연스러움 최고

### 1. Gemini 3 Deep Think

**기술 요약:** Google DeepMind의 특화 추론 모드. 여러 추론 경로를 병렬 탐색하여 최적해를 도출한다. 수학 올림피아드 금메달 수준, ARC-AGI-2 84.6% 달성.

**적용 가능성:** HIGH

**접목 아이디어:**

SNS 데이터가 추가되면 Deep Think의 활용도가 더 높아진다. Instagram 사진 20장의 색조/분위기 + X 트윗의 성격 키워드 + 설문 4개 답변을 Deep Think가 병렬 추론으로 종합해 세계관을 설계한다.

- **SNS + 설문 종합 해석:** "다크 판타지 + 고독한 안티히어로" 같은 세계관을 데이터 기반으로 설계
- **보스 AI 전략 설계:** Deep Think로 플레이어 전투 패턴 분석 → 플레이어를 읽는 보스 구현
- **로딩 UX 연출:** 응답 시간이 길어지는 점을 역으로 활용 → "Gemini가 당신의 세계를 설계 중입니다..." 연출

```python
world_design = gemini.generate(
    model="gemini-3-deep-think",
    prompt=f"""
    [SNS 분석 결과] {sns_analysis}
    [설문 답변] {survey_answers}
    위 데이터를 종합하여:
    1. 세계관의 색조 팔레트 (hex 코드 5가지)
    2. 던전 분위기 서술 (2문장)
    3. 보스의 성격 archetype
    4. 배경음악 감성 키워드 (Lyria 3 프롬프트용)
    를 설계하라.
    """,
    use_deep_think=True
)
```

**구현 난이도:** 해커톤 내 충분히 적용 가능. 기존 Gemini 통합 코드에서 설문 해석 함수 한 곳만 Deep Think로 교체.

**기대 효과:**
- SNS + 설문 종합 해석 → 세계관 일관성 및 개인화 품질 극대화
- "AI가 정말 나를 이해했다"는 감정적 몰입
- Google 최신 기술 스택 풀 활용 → 심사 기준 충족

### 2. Lyria 3

**기술 요약:** Google DeepMind의 음악 생성 AI. 텍스트/이미지 프롬프트로 가사-보컬-커버아트 포함 30초 커스텀 트랙 생성. Lyria RealTime API는 WebSocket 기반 2초 청크 스트리밍으로 실시간 인터랙티브 음악 지원. 한국어 공식 지원.

**적용 가능성:** HIGH

**접목 아이디어:**

게임에서 이미 시각(캐릭터)과 서사(GM)를 다루고 있으므로, 청각 레이어 추가가 몰입도의 결정적 차이를 만든다.

- **플레이어 테마송 생성 (데모 최강 카드):** 서베이 완료 직후 플레이어 응답 데이터를 Lyria 3 프롬프트로 변환 → 그 사람만의 테마 BGM 생성. "이제 당신의 테마송이 생성됩니다" → 30초 후 실제 음악 재생
- **전투 상황별 동적 BGM (RealTime API):** 보스 등장 → 긴장감 단조 / 전투 중 → 빠른 템포 / 플레이어 위기 → 어두운 편곡 / 승리 → 밝은 팡파르. 2초 청크 스트리밍으로 seamless 전환
- **이미지-투-뮤직:** Nano Banana 2 Flash가 생성한 배경 이미지를 Lyria 3에 입력 → 해당 씬의 BGM 자동 생성. 텍스트 프롬프트 작성 없이 시각-청각 동기화 달성
- **보스 테마 자동 생성:** 각 보스 외형(AI 생성 스프라이트)을 Lyria 3에 입력 → 보스 전용 전투 테마 개인화

**구현 난이도:** 즉시 가능 (1-2시간). Gemini 앱에 이미 통합, 한국어 지원, 추가 인증 불요.

**기대 효과:**
- 시각 + 청각 + 서사 동시 개인화 → "이 게임이 나를 위해 만들어졌다" 경험 완성
- 이미지 생성은 많은 팀이 하지만, BGM까지 개인화하는 팀은 드물다 → 경쟁 차별화
- RealTime API 스트리밍 기반으로 추가 비용 미미 → $0.49/세션 유지

### 3. A2UI (Agent-to-User Interface)

**기술 요약:** Google이 2025년 12월 공개한 에이전트 주도 UI 스트리밍 프로토콜. AI 에이전트가 선언적 JSON으로 풍부한 UI 컴포넌트를 동적 생성하여 프론트엔드에 전송. 카탈로그 기반 보안 모델. v0.8 Public Preview.

**적용 가능성:** HIGH

**접목 아이디어:**

Gemini GM의 설문 → 세계관 색채화 구간이 A2UI의 최고 활용처.

**1. 동적 설문 UI 생성:** 텍스트 Q&A 대신 Gemini가 설문 맥락에 맞는 UI를 JSON으로 직접 생성. 선택지가 버튼이 되고, 선택 결과가 즉시 에이전트로 피드백. 탭/클릭으로만 설문 완료.

```json
{
  "component": "ChoiceCard",
  "props": {
    "question": "당신이 가장 두려워하는 것은?",
    "choices": [
      { "icon": "fire", "label": "타오르는 불꽃", "value": "fire" },
      { "icon": "darkness", "label": "끝없는 어둠", "value": "darkness" }
    ],
    "style": "rpg-survey"
  }
}
```

**2. 세계관 프리뷰 카드:** Gemini가 설문 답변 분석 후 세계관 프리뷰 카드를 실시간 렌더링. 설문 진행에 따라 카드가 점진적 업데이트 → 세계가 실시간으로 색칠되는 효과.

**3. 전투 UI 동적 생성:** 보스 상태(분노, 체력 임계값)에 따라 전투 옵션 UI를 동적으로 변경.

**구현 난이도:** 적용 가능하나 범위 한정 필요. v0.8 Preview라 전체 스택 도입은 리스크 높음. 실용적 대안: A2UI 개념만 차용하여 Gemini Structured Output + 프론트엔드 JSON 파싱으로 경량 구현. 설문 파트 1-2개 질문에만 적용해도 데모 효과 충분.

**기대 효과:**
- 설문이 채팅이 아닌 인터랙티브 RPG 경험으로 변환
- "AI가 UI까지 직접 생성한다"는 데모 임팩트
- 설문 완료 속도 향상 → 게임 본편 진입 시간 단축

### 4. PaperBanana

**기술 요약:** 학술 논문 삽화 자동 생성 5-에이전트 멀티파이프라인. Retriever → Planner → Stylist → Visualizer → Critic 순서로 레퍼런스 기반 고품질 이미지 생성. 최대 20개 후보 병렬 생성 후 Critic이 폐쇄 루프로 품질 개선.

**적용 가능성:** HIGH

**접목 아이디어:**

5단계 파이프라인 구조가 게임의 캐릭터 에셋 생성 파이프라인과 직접 대응된다. 단, **실시간 에셋과 백그라운드 에셋에 다른 전략을 적용**해야 한다.

**전략 A: 스타일 앵커링 (실시간 생성 에셋용 — 경량)**

설문 중 즉시 보여줘야 하는 파티원 스프라이트/일러에는 Critic 루프를 끼울 시간이 없다. 대신 첫 번째 생성 이미지의 설명을 후속 프롬프트에 레퍼런스로 주입해서 스타일을 고정한다. 추가 API 호출 없음 → 대기 시간 0.

```python
first_sprite_desc = "48x48 pixel art, warm palette, soft edges, fantasy style"
prompt = f"Style reference: {first_sprite_desc}. Now generate: {new_character_desc}"
```

**전략 B: Critic 루프 (백그라운드 생성 에셋용 — PaperBanana식)**

전투 중/대화 중에 백그라운드에서 미리 생성하는 에셋에는 시간 여유가 있으므로 Critic 루프를 적용한다.

```
[생성] Nano Banana 2 Flash: 다음 스테이지 배경/보스 아트
    ↓
[검수] Gemini: "JRPG 스타일 일치? 이전 에셋과 화풍 일관? 부적절 콘텐츠?"
    ↓
  통과 → 대기열에 저장
  실패 → 프롬프트 수정 후 재생성 (최대 1회)
```

**에셋별 적용 구분:**

| 에셋 종류 | 생성 시점 | 품질 전략 | 이유 |
|-----------|----------|----------|------|
| 파티원 도트 (4장) | 설문 중 실시간 | 앵커링만 | 즉시 보여줘야 함 |
| 파티원 일러 (12장) | 설문 중~타이틀 전환 | 앵커링만 | 대기 시간 불가 |
| 보스 일러 (3장) | 전투 전 백그라운드 | **Critic 루프** | 파티 소개 화면 동안 시간 있음 |
| 다음 스테이지 배경 | 전투 중 백그라운드 | **Critic 루프** | 5-10턴 동안 충분한 시간 |
| 다음 보스 아트 | Phase 2 대화 중 | **Critic 루프** | GM 대화가 시간 벌어줌 |

- **배치 병렬 생성:** PaperBanana의 "최대 20개 병렬 생성" 전략을 그대로 적용. 설문 중 백그라운드에서 에셋 병렬 생성 → 대기 시간 제로 달성

**구현 난이도:** 파이프라인 구조만 차용해 직접 구현 가능 (2-3시간). 앵커링은 프롬프트 주입(30분), Critic 루프는 검수 프롬프트 + 분기 로직(1시간).

**기대 효과:**
- 실시간 에셋은 앵커링으로 빠르게, 백그라운드 에셋은 Critic으로 확실하게 — 상황에 맞는 이중 전략
- 대기 시간 제로 + 스타일 일관성 → 게임의 2대 기술적 우려 동시 해결

### 5. Recursive Language Model (RLM)

**기술 요약:** MIT CSAIL의 RLM은 LLM이 복잡한 작업을 재귀적으로 하위 작업으로 분해하고, 자기 자신을 서브에이전트로 호출하여 처리. 컨텍스트 윈도우 최대 100배 초과 입력 처리 가능. Google ADK BaseAgent 위에서 구현. 자기 검증(Generate → Evaluate → Refine) 루프.

**적용 가능성:** HIGH

**접목 아이디어:**

Gemini Game Master의 세계 구성 로직을 RLM 패턴으로 설계:

```
GameMaster(플레이어 전체 프로파일) ← 최상위 호출
    ↓ 재귀 분해
    ├── WorldBuilder(설문 응답 분석) → 세계관 방향성 결정
    │       ↓
    │       ├── NarrativeAgent(스테이지 스크립트 생성)
    │       ├── VisualPromptAgent(이미지 프롬프트 × 14~19개 병렬 생성)
    │       └── BossPersonalityAgent(보스 AI 성격 프로파일)
    ↓
    자기 검증: "이 세계관이 플레이어 설문과 일치하는가?" → 불일치 시 재귀 개선
```

- GameMaster가 상위 세계관을 확정 → 하위 에이전트들이 병렬로 에셋 프롬프트 분산 생성
- 전투 중 보스 AI의 자기 개선 루프에도 적용 가능
- ADK BaseAgent 기반이므로 Google 기술 스택과 자연스럽게 통합

**구현 난이도:** 부분 적용 가능 (2-3시간). 재귀 깊이를 2단계(GameMaster → 병렬 서브에이전트)로 고정. 병렬 프롬프트 분해 + 자기 검증 루프 2가지만 구현해도 충분.

**기대 효과:**
- 이미지 생성 대기시간 0 전략과 시너지: 상위 에이전트가 세계관 확정하는 동안 하위 에이전트들이 에셋 프롬프트 병렬 미리 생성
- 설문 → 세계관 → 에셋 파이프라인의 품질과 일관성이 자기 검증으로 향상
- ADK 채택 → "Google ADK 미활용" 기존 약점 해소

### 6. Budget-Aware Tool Calling (BATS)

**기술 요약:** 도구 호출 예산을 단순히 늘려도 성능이 향상되지 않는다는 발견. Budget Tracker(예산 실시간 추적) + BATS(예산에 따라 탐색/수렴 전략 동적 전환) 제안.

**적용 가능성:** MEDIUM

**접목 아이디어:**

$0.49/세션 비용 목표에 "예산 인식 → 전략 적응"이 직접 적용된다.

```python
class GameSessionBudget:
    TOTAL_BUDGET = 0.49
    budget_allocation = {
        "survey_gm": 0.08,
        "boss_ai": 0.12,
        "image_generation": 0.24,
        "narrative": 0.05
    }
    def adjust_strategy(self, remaining_budget, current_phase):
        if remaining_budget > 0.3:  return "exploratory"   # 풍부한 응답
        elif remaining_budget > 0.15: return "balanced"     # 핵심만
        else: return "convergent"                           # 최소 토큰
```

- 이미지 생성 예산 적응: 여유시 고해상도 전체 생성, 빠듯하면 핵심 스프라이트만 + 프리셋 배경
- Gemini GM 토큰 적응: 예산 충분 → 풍부한 내러티브, 빠듯 → 핵심 키워드만 추출

**구현 난이도:** 부분 적용 가능 (2-3시간). 세션 예산 딕셔너리 + 각 AI 호출 후 비용 차감 + 잔여 예산 분기 처리.

**기대 효과:** $0.49/세션 비용 목표를 실제로 달성할 가능성 향상. 데모 리스크 감소.

### 7. CogRouter (Think Fast and Slow)

**기술 요약:** LLM 에이전트가 각 단계마다 인지 깊이(Level 1~4)를 동적으로 선택. GPT-4o 대비 62% 적은 토큰으로 더 높은 성능 달성.

**적용 가능성:** MEDIUM

**접목 아이디어:**

Gemini의 `thinking_budget` 파라미터를 상황별로 다르게 설정:

| 게임 상황 | 인지 수준 | thinking_budget |
|-----------|-----------|-----------------|
| 설문 답변 수신 / 일반 대화 | Level 1-2 | 128 (낮음) |
| 전투 중 보스 일반 공격 | Level 2 | 256 |
| 보스 전략적 스킬 판단 | Level 3 | 1024 |
| 세계 색채화 결정 / 스토리 분기점 | Level 4 | 2048 (높음) |

**구현 난이도:** 30분~1시간. Gemini API 호출 시 유틸리티 함수 하나로 구현.

**기대 효과:** 전투 응답 속도 향상 + 세션당 토큰 비용 15-30% 절감.

### 8. Feeling Social

**기술 요약:** LLM 챗봇이 플레이어 성향에 맞춰 사회적 응답 전략을 진화적으로 조정하는 프레임워크. 80가지 사회적 조절 전략 중 상황에 맞는 것을 선택해 시스템 프롬프트에 자동 반영.

**적용 가능성:** MEDIUM

**접목 아이디어:**

Game Master의 대화 스타일을 플레이어 성향에 적응시킨다.

- 서베이 단계에서 플레이어 대화 스타일 분류 (내향/외향, 낙관/염세)
- 성향별 GM 프롬프트의 "말투 지시 블록" 교체:
  - 낙관적 → 감정적 증폭: 승리 장면을 더 극적으로 묘사
  - 염세적 → 감정적 수용: 패배 시 공감 먼저, 다음 전략 안내
- 보스 대사에도 반영: 플레이어 성향을 파악한 심리전 도발 대사 ("넌 항상 포기했잖아...")

**구현 난이도:** 부분 가능 (2-3시간). 신경진화 엔진(Async-NEAT)은 불가. 3가지 성향 분류 + 성향별 프롬프트 블록 교체로 경량 구현.

**기대 효과:** 같은 게임이라도 플레이어마다 다른 GM 경험 → 재플레이 가치 상승. "이 AI는 나를 알아요" 인상.

### 10. ToolOrchestra

**기술 요약:** NVIDIA NVlabs의 엔드투엔드 RL 프레임워크. 8B 파라미터 소규모 오케스트레이터가 다양한 전문 도구와 모델을 전략적 조율. GPT-5 대비 30% 비용으로 동등 이상 성능.

**적용 가능성:** MEDIUM

```
[GameOrchestrator - 소규모 라우터]
```

**구현 난이도:** 충분히 적용 가능 (2-3시간). RL 훈련 불필요, 설계 패턴만 차용.

**기대 효과:** 모든 Google AI 도구를 단일 오케스트레이터가 조율하는 깔끔한 아키텍처 완성. 불필요한 Gemini 호출 차단으로 비용 제어.

### 11. MACLA (Hierarchical Procedural Memory)

**기술 요약:** LLM 에이전트가 과거 경험에서 재사용 가능한 절차를 자동 추출하고 베이지안 신뢰도로 품질 추적. 2,851개 궤적 → 187개 절차 압축.

**적용 가능성:** LOW (하향 조정)

**판단 근거:** MACLA는 대규모 경험 축적(수천 개 궤적)을 전제로 한다. 실제 게임 세션의 입력량은 설문 4개 + 전투 5-10턴으로, 계층적 메모리를 구축하기에 데이터가 턱없이 부족하다. 보스가 "학습한다"는 효과는 **직전 2-3턴 히스토리를 프롬프트에 넣는 슬라이딩 윈도우** 방식으로 충분히 달성 가능.

**활용 방법:** 멀티 세션 데이터 축적이 가능한 프로덕션 단계에서 재검토. 해커톤에서는 단일 game_state dict로 대체.

### 12. AlphaEvolve

**기술 요약:** Google DeepMind의 Gemini 기반 진화적 알고리즘 설계 에이전트. LLM 코드 생성 + 자동 평가자 + 진화 루프로 수십만 개 코드 변이를 탐색.

**적용 가능성:** LOW

**판단 근거:** AlphaEvolve가 풀려는 문제(수십만 번 반복 최적화)는 해커톤 게임과 거리가 멀다. 해커톤 맥락에서 언급하면 오히려 과잉 설계로 보일 수 있음.

**활용 방법:** 피치 스토리텔링 용도로만. "보스 AI가 진화적으로 최적화된 전투 패턴을 학습한다"는 내러티브에서 AlphaEvolve를 레퍼런스로 언급하면 기술적 깊이 어필 가능.

---

### 13. OpenEvolve

**기술 요약:** AlphaEvolve의 오픈소스 재현. LLM diff 기반 코드 변이 + MAP-Elites + 섬 모델로 진화적 코드 최적화. Gemini-3-Flash 기준 반복당 $0.01-0.05.

**적용 가능성:** LOW

**판단 근거:** AlphaEvolve와 동일한 이유로 직접 적용 불가.

**활용 방법:** MAP-Elites의 이중 선택 개념(성능 기반 vs 영감 기반)만 차용. 보스 행동 풀을 `(공격성, 방어성)` 2차원으로 분류 → Gemini가 최적 사분면의 전술을 선택하는 프롬프트 설계에 30-60분 투자 가능.

---

### 14. DSPy

**기술 요약:** Stanford NLP의 프롬프트 자동 최적화 프레임워크. 시그니처(선언) + 자동 최적화기로 LLM 파이프라인 구축.

**적용 가능성:** LOW (해커톤 맥락 기준)

**판단 근거:** DSPy의 핵심 가치인 Optimizer는 학습 데이터셋 + 메트릭 정의가 필요 → 해커톤에서 준비 불가. Signature 개념만 차용하면 일반 함수 구현과 체감 차이 없음. 학습 곡선 + 한국어 최적화 불확실성 감안 시 리스크 대비 효익 낮음.

**활용 방법:** 해커톤 이후 프로덕션 단계에서 사용자 플레이 데이터가 쌓이면 GM 파이프라인 자동 최적화에 도입 권장.

---

### 15. Tolvera

**기술 요약:** Taichi Lang 기반 GPU 가속 파티클 시뮬레이션(Boids, Physarum, Reaction-Diffusion) 실시간 렌더링 툴킷. OSC/MIDI 프로토콜로 음악-비주얼 실시간 연동.

**적용 가능성:** LOW

**판단 근거:** Taichi Lang + GPU 환경 셋업만 1-2시간. 게임 스택과 완전히 다른 기술 도메인. 7-8시간 해커톤에서 ROI 매우 낮음.

**활용 방법:** "파티클 기반 세계 채색" UX 아이디어만 채용. 설문 응답이 들어올 때마다 CSS/Canvas API로 파티클이 퍼져나가며 색상이 채워지는 경량 애니메이션 구현 (30-60분).
